## 1. 形态与选型

第一期是 **移动端优先的静态网页**，不是微信小程序。扫码打开的是 GitHub Pages 的 https 地址。

| 点 | 选择 | 理由 |
|---|---|---|
| 框架 | Vue 3（与 `dafushan-guide` 相同） | 仓库里已有同一套，少切换成本 |
| 构建 | Vite | 同上 |
| 路由 | Vue Router + **Hash** | GitHub Pages 项目页没有后端，Hash 不需要 404 回退 |
| 组件库 | 无 | 三个页面，自己写；避免把练习页做成后台 |
| 后端 | 无 | 第一期无登录；数据在浏览器 |
| 存储 | IndexedDB | 曲谱是图片，localStorage 约 5MB 装不下 |
| 发布 | `gh-pages` 分支上的 `/rike/` 目录 | 与大夫山共存，禁止整分支重建把导览冲掉 |

目录：`personal-projects/rike/`。  
线上地址：`https://starfish85.github.io/personal-projects/rike/`。

以后迁小程序：页面已经按「今日 / 曲谱 / 笔记」拆开；定位无关，主要改文件选择和存储为 `wx.*` API。

## 2. 为什么 IndexedDB，以及怎么建模

localStorage 存字符串，容量小，不能可靠放 Blob。IndexedDB 能放二进制，刷新还在，够用。

原则：**数据按任务、日期记录和本机图片资产建模。**

### 2.1 对象仓库

- `kv`：键值。任务、某天进度、杂项配置。
- `assets`：图片资源。`keyPath = id`，索引 `(taskId, role)`。
- `strokes`：`keyPath = assetId`，一份曲谱对应一份笔迹列表。

### 2.2 键与形状

```text
kv["tasks"] = [
  {
    id, title, template, completion, color, reminder,
    components, subtasks, dueDate, longTerm, repeatWeekdays,
    paused, archived, order, pinned
  }
]

kv["day.guitar.2026-08-21"] = {
  count: 7,
  completedAt: "2026-08-21T12:03:11.000+08:00" | null,
  subtasks: { subtaskId: true }
}

assets[] = {
  id, taskId: "guitar",
  role: "sheet" | "note",
  name, mime, width, height,
  createdAt, order,
  blob,        // 压缩后的图片
  thumbBlob    // 缩略图
}

strokes[] = {
  assetId,
  strokes: [
    { tool: "pen" | "eraser", color, width, points: [{x, y}, ...] }
  ]
}
```

说明（给实习生）：

- `day.*` 按天分条，而不是只存「当前数字」。这样二期做日历时，历史天数已经在。
- `role` 把曲谱和笔记分开。二期的画画打卡用 `checkin` 即可，不必改仓库。
- `repeatWeekdays` 存 ISO 周序，`1 = 周一`，`7 = 周日`。长期任务如果为空，就每天出现；如果有值，就只在这些周几出现。
- 笔迹坐标用 **0～1 相对图片宽高**，不存屏幕像素。否则换手机、旋转、缩放，圈会飞走。
- `width` 也是相对值（相对 min(图宽, 图高)），粗细跟谱走。

第一期组件可以叫 `Today.vue`，但判断完成时读 `task.target` 和 `day.count`，不要写死 `if (count >= 10)`。

## 3. 图片管道

1. `<input type="file" accept="image/*" multiple>`。不设 `capture`，默认相册，用户仍可改拍照。
2. `createImageBitmap` 读图；失败则视为 HEIC / 损坏，提示换 jpg/png。
3. 压缩：最长边 2560，jpeg 质量 0.86，保证六线谱可辨且 canvas 不太卡。
4. 缩略图：最长边 360。
5. 写入 IndexedDB。配额失败要 catch，把 PRD 第 7 节文案抛到 Toast。

页面展示用 `URL.createObjectURL(blob)`，组件卸载或换图时 `revoke`，防止内存泄漏。

## 4. 曲谱视口

结构：

```text
.viewport   overflow: hidden; 全屏
  .stage    width/height = 该页 contain 进视口后的尺寸
            transform: translate(tx, ty) scale(s); transform-origin: 0 0
    img
    canvas  与 img 叠同尺寸；内部像素 = 图片宽高
```

- 进入一页：计算 contain 的 `baseW/baseH`，`scale=1`，居中。
- 缩放围绕双指中点或按钮中心：先把屏幕点换成舞台坐标，改 scale，再反推 tx/ty，让手指下的谱点不动。
- `touch-action: none`，`overscroll-behavior: none`，阻止微信/Safari 把下拉刷新抢走。
- 浏览模式单指改 tx/ty；画笔模式单指把点丢给标注；**双指永远走缩放**。

标注绘制：

- 画笔：`source-over`。
- 橡皮：`destination-out`。
- 每一笔是点列，圆角线。撤销 = pop 最后一笔后重放。
- 为避免每一帧重放上百笔卡死：维护一张「已提交」离屏 canvas，当下这一笔画在上面；撤销才全量重放。

## 5. 日期

```js
function localDateKey(d = new Date()) {
  const y = d.getFullYear()
  const m = String(d.getMonth() + 1).padStart(2, '0')
  const day = String(d.getDate()).padStart(2, '0')
  return `${y}-${m}-${day}`
}
```

禁止 `toISOString().slice(0, 10)`。那是 UTC。

`visibilitychange` 为 `visible` 时重新核对日期。

## 6. 路由

| Hash | 页 | keep-alive |
|---|---|---|
| `#/` | 今日练习 | 否 |
| `#/sheet/:taskId?` | 曲谱 | 建议是，减少回首页再进的重解码 |
| `#/notes/:taskId?` | 笔记库 | 否 |

笔记覆盖层是曲谱页的子组件，不占路由。

GitHub Pages `base`：发布时 `/personal-projects/rike/`，本地 `./`。与大夫山同一套路。

## 7. 备份格式（P1）

单文件 JSON：

```text
{
  app: "rike",
  version: 3,
  exportedAt,
  kv: { ...所有 kv },
  assets: [{ ...元数据, blobBase64, thumbBase64 }],
  strokes: [...]
}
```

导入：校验 `app === "rike"`，清空三张表，再写入。图片多时文件会大，第一期可接受（私人备份，不走网络）。

## 8. 发布

`scripts/publish-pages.sh`：

1. `GITHUB_PAGES=true npm run build`
2. **clone 已有 `gh-pages` 分支**（不要 `git init` 后 force push 整个分支）
3. 只更新 `rike/` 目录
4. 提交并 push
5. 用本地工具生成二维码到 `rike/public/qr.png`（源码树一份即可）

大夫山的 `/dafushan-guide/` 必须原样保留。

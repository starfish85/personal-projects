## Overview

在五问题硬化之后，日课能用，但还不够「每天坐下就顺」。本方案覆盖你点名的十件事，再加一条实测出来的阻塞：

0. **组件要真的出现**（完成方式 vs 附加组件）。不修这条，后面的时长、当前曲、健身传图都会踩在错误的任务类型上。
1. **现有摩擦**：新建弹窗、备份入口、曲谱 HUD、首页卡片菜单。
2. **练习闭环**：时长、连续天数、当前曲、跳过某一天、周视图、健身传图算一遍。

不改云同步范围（图仍只在本机），不加社交，不做按日实例表的完整版——跳过某天只用任务上的 `skipDates` 黑名单。本轮先出方案，不改代码。

## 实测：添加组件之后

2026-08-26 用本机 Chrome（390×844，触控，空档案）对本地 `http://127.0.0.1:5174/` 点过 12 个场景。IndexedDB 里的任务对象和屏幕对得上。

### 过了的

| 场景 | 结果 |
|---|---|
| 自定义保存后首页有任务 | 有 |
| 后加曲谱/笔记/番茄钟，再打开编辑 | 开关记住了 |
| 刷新后后加的曲谱/笔记/番茄钟 | 详情里还在 |
| 取消番茄钟 / 取消曲谱 | 对应入口消失 |
| 乐器模板默认 | `练完一遍` + 番茄钟/批注/曲谱/笔记 |
| 画画勾曲谱 | Draw 页有曲谱入口，能进 `/sheet/:id` |
| 健身勾曲谱 | RichTask 有曲谱入口 |
| 自定义勾曲谱后点入口 | 停在该任务的空谱页 |
| 日历每天汇总 | 还在 |

所以「组件完全没落库」不成立。`updateTask` 会写 `components`，CheckTask / Draw / RichTask 也都挂了 `TaskHelpers`。用户看见「没出现」，是另一类错。

### 没过的（用户会当成没加上）

| # | 场景 | 落库 | 屏幕 | 根因 |
|---|---|---|---|---|
| A | 自定义勾「计数器」（只勾或全开） | `components` 含 `counter`，**`completion` 仍是 `check`** | 「完成今天」，没有「练完一遍」；首页仍是空心勾 | `toggleComponent` 只改数组；`addTask`/`updateTask` 不改 `completion`；`Task.vue` 按 `completion` 路由 |
| B | 生活习惯勾计数器 | 同上 | 仍是打卡 | 同 A |

| D | 全开组件的自定义 / 乐器 | 曲谱、笔记在 DOM 里 | **首屏 844 高看不到**（曲谱 y≈916） | 番茄钟面板太高，入口在计时器下面 |
| E | 非计数任务进曲谱 | 能进 | HUD 计数 pill 显示 `0 / undefined`，点 + 会写 `count` | `Sheet.vue` 无条件挂 `PracticeCounter`；check 任务没有 `target` |

| G | 健身再勾曲谱 | `images` + `sheet` | 「插入图片 · 本机保存」，作品墙入口没了 | `taskLogsImages`：**有谱就不当打卡图** |

首页卡片：勾了计数器的自定义任务右侧仍是打卡圈，副文案「今日未完成」，看起来类型没变。

### 代码路径（不要再猜）

```
编辑芯片 → form.components
         → savePayload() 不含 completion（编辑）/ 用模板 completion（新建）
         → addTask / updateTask
Task.vue  kind = task.completion        ← 不看 components
RichTask  PracticeCounter = taskHasComponent('counter')
CheckTask / Draw  只有 TaskHelpers，没有计数器
normalizeTask     sheet/notes = completion==='counter' && has(sheet|notes)
taskLogsImages    has(images) && !has(sheet)
```

伪组件 `'check'` 会写进自定义/习惯的 `components`，芯片列表里没有对应项。

## Key Decisions

1. **弹窗：名称只采用 `defaultTitle`。** 自定义 `defaultTitle === ''`，名称保持空。乐器仍预填「练习乐器」。
2. **保存条贴在弹窗底部（sticky），不随表单滚走。** `saving` 时只禁用保存；取消始终可点。保存中点取消 = `requestClose`（进行中仍不中断写盘，但失败后可立刻关）。
3. **备份入口进 `SyncBar`，和云同步并列。** 云同步仍然不同步图；文案写明「曲谱和打卡图只在这台手机」。
4. **超过 7 天没导出，首页出现一次轻提示（每会话最多一次）。** 不弹模态。导出成功写入 `kv.lastBackupAt`。
5. **首页主入口改成卡片右侧「⋯」+ 长按同一菜单。** 左滑保留一版但不再当唯一入口；本轮不删滑动手势，避免突然不会改任务。
6. **曲谱顶栏只留：返回、当前曲/页码、笔记。** 有谱时计数和工具在底栏；空谱不渲染 `PracticeCounter`。
7. **时长只从计时器会话累加。** 不按「对着谱发呆」自动计。暂停 / 到点 / 离开页面时，把本段秒数加进 `day.{taskId}.{date}.seconds`。
8. **连续天数是算出来的，不存库。** 从今天或昨天沿「应出现的日子」往回数，`skipDates` 和未排的周几不打断。
9. **当前曲是任务内的分组，不是新任务。** 页属于 `pieceId`；`bump` 加在当前曲上。旧谱没有分组 → 默认「未分组」。
10. **跳过某一天 = `task.skipDates: ['YYYY-MM-DD']`。** 只作用于今天和未来；已有活动的过去日仍按档案显示。
11. **周视图是日历的第二种格子，不是新路由。** 月/周切换；完成度用现有 `dayComplete`。
12. **健身（`taskLogsImages` + counter）：每成功上传 1 张打卡图，`count += 1`。** 删图 `count -= 1`（不低于 0）。**不再**用 `syncPhotoDay` 把 count 覆盖成张数。完成判定仍是 `count >= target`。
13. **完成方式和附加组件分开。** 完成方式三选一：打卡 / 计数 / 传图。芯片只保留番茄钟、插入图片、批注、曲谱、笔记。不再把「计数器」混在芯片里。
14. **页面路由仍看 `completion`，但编辑器改完成方式必须写进任务。** 选「计数」→ `completion='counter'` + `components` 含 `counter` + 默认 `target=10`。详情出现「练完一遍」，首页不再画勾子。
15. **`components` 只存真实芯片 id。** 丢掉伪组件 `'check'`。`normalizeTask` 的 `sheet`/`notes` 布尔跟随 `components`，不跟 `completion`。
16. **学习模板改成打卡 + 番茄钟 + 笔记。** 和文案「番茄钟、笔记、可添加子任务」一致；主操作是「完成今天」，不是遍数。
17. **曲谱/笔记入口放在番茄钟上面。** 390 高首屏必须能看见。曲谱 HUD 的计数 pill 仅 `completion==='counter'`。
18. **`taskLogsImages`：有 `images` 且 `completion==='counter'` 就是打卡图，不再用「有谱」互斥。** `photo-log` 任务不在 Helpers 里再画一遍插入图片。

## 0. 组件要真的出现

阻塞。不进 PR1–7 的体验项之前先做。

### 编辑器

`Home.vue` 详情步，芯片上拆一行：

```
完成方式
  [打卡] [计数] [传图]

组件
  [番茄钟] [插入图片] [批注] [曲谱] [笔记]
```

`TASK_COMPONENTS` 去掉 `counter`。选「计数」时下面出现目标遍数（默认 10，和现在新建 counter 一样）。

模板只是预设这两行：

| 模板 | 完成方式 | 默认组件 |
|---|---|---|
| 乐器练习 | 计数 | 番茄钟、批注、曲谱、笔记 |
| 画画 / 创作 | 传图 | 批注、笔记（上传由 Draw 主按钮负责，不再默认勾插入图片） |
| 学习 / 备考 | 打卡 | 番茄钟、笔记 |
| 健身 / 康复 | 计数 | 番茄钟、插入图片、笔记 |
| 生活习惯 | 打卡 | 笔记 |
| 自定义 | 打卡 | 无 |

已改过的完成方式 / 组件，换模板时不要覆盖（和名称规则同一套：用户动过的留下）。

### 写入

```js
function completionFromForm() {
  return form.completion // 'check' | 'counter' | 'photo-log'
}

function componentsFromForm() {
  const ids = form.components.filter((id) => id !== 'check' && id !== 'counter')
  if (form.completion === 'counter') ids.unshift('counter')
  return [...new Set(ids)]
}
```

- `savePayload` / `addTask` / `updateTask` **都带 `completion`**。
- `updateTask` 增加：`if ('completion' in patch) task.completion = patch.completion`；切到 `counter` 时若没有 `target` 设 10；切走 `counter` 时保留旧 `target` 但不展示。
- `toggleComponent` 不再碰 `completion`。完成方式用三个按钮设 `form.completion`。
- `ensureRichComponents` 删除。新建 counter 不再在空数组时填满默认六件套。

### 详情

`Task.vue` 继续按 `completion` 分发，不重做成单页。

- `counter` → RichTask。`PracticeCounter` 条件改成 `practice.task.completion === 'counter'`（有子任务也要显示；子任务当清单，不挡主操作）。
- `photo-log` → Draw。`TaskHelpers` 对 `images` 返回 false（主按钮已经是上传）。
- `check` → CheckTask。Helpers 照常。

`taskHasComponent('counter')` 仍可用于别处，但主操作不要只信它。

### 兼容（打开旧任务时 `normalizeTask`）

1. 丢掉 `components` 里的 `'check'`。
2. `sheet` / `notes` = `componentSet.has('sheet'|'notes')`，**不论** completion。
3. 若 `components` 含 `counter` 且 `completion==='check'` → 升为 `counter`（用户勾过计数器，按他的意图补上）。
4. 若 `completion==='counter'` 且不含 `counter`（旧学习模板）→ 改成 `check`，保留番茄钟/笔记。已有 `count` 的日子仍留在 `day.*`，只是完成判定改走打卡。
5. 画画旧数据 `components` 含 `images`：保留字段，Draw 页不渲染 Helpers 的图片面板即可，避免两套上传。

### 曲谱 HUD（与第 3 节同一规则，这里先钉死）

`Sheet.vue` 的 `PracticeCounter`：`v-if="practice.task.completion === 'counter'"`。非计数任务顶栏不要 `0 / undefined`。

### 图片角色

```js
export function taskLogsImages(task) {
  const components = Array.isArray(task.components) ? task.components : []
  if (!components.includes('images')) return false
  if (task.completion === 'photo-log') return false
  return task.completion === 'counter'
}
```

健身勾了曲谱，插入图片仍是打卡图，作品墙还在。吉他默认没有 `images`，不受影响。自定义打卡 + 插入图片 = 本机附件，不算完成。

### 验收

- 自定义 → 完成方式改计数 → 保存 → 详情「练完一遍 0/10」，首页无勾子。
- 自定义 → 只勾曲谱/笔记/番茄钟 → 详情是「完成今天」+ 三个入口，曲谱/笔记在番茄钟上面、首屏可见。
- 习惯改成计数 → 变成计数任务。
- 学习模板 → 「完成今天」+ 番茄钟 + 笔记。
- 画画 → 只有一套上传；再勾曲谱，曲谱入口在，上传仍是打卡。
- 健身勾曲谱 → 仍是「图片打卡」不是「本机保存」，有作品墙。
- 刷新后 `sheet`/`notes` 布尔与芯片一致。
- 非计数任务曲谱页没有 +1 pill。

## 1. 新建任务弹窗

文件：`src/pages/Home.vue`

完成方式那一行见第 0 节，和名称、sticky 保存条同一弹窗，同一 PR 也可以，但数据绑定必须先于文案微调。

**名称**

```js
form.title = item.defaultTitle || ''
```

不要回落到 `item.title`。选「自定义」名称空；选「乐器练习」仍是「练习乐器」。用户已改过的名称，选模板时若不等于任何模板名，保留。

**布局**

`.modal-sheet` 内部分成可滚动主体 + 底部 `position: sticky; bottom: 0` 的 `.modal-actions`（背景用 `--bg-elev`，顶线 `--line`）。打开时就能看到保存。

**取消**

去掉取消按钮的 `:disabled="saving"`。`requestClose` 在 `saving===true` 时仍 return（避免写到一半关窗导致状态乱）；**失败后 `saving` 已是 false**，取消可关。toast 改到弹窗上方或 `margin-bottom` 避开按钮行。

验收：选自定义 → 名称空 → 保存 →「先写任务名称」，取消能关；表单一长也能点到保存。

## 5. 时长

**数据**（`day.{taskId}.{date}` 增字段，旧记录当 0）

```js
seconds: number  // 今日累计，整数
```

**写入**

番茄钟 / 正计时在「暂停、到点结束、离开任务页、组件卸载」时：

```
elapsed = 本段实际走过的秒
day.seconds += elapsed
```

倒计时用 `设定分钟 - 剩余`；正计时用当前秒数相对本段起点。不把重置后的 0 写成负的。

**展示**

- 首页副文案：有秒则加 ` · 23 分钟`（四舍五入到分钟，不足 1 分钟且 >0 显示 `不足 1 分钟`）
- 日历任务行同样
- 不显示 0 分钟

**非目标：** 不根据曲谱停留自动计时。

## 6. 连续天数

纯函数 `streakFor(task, today, daysByTask)`：

1. 若今天已完成，从今天往回；否则从昨天往回。
2. 对每一天：若 `skipDates` 包含，或 `!taskOnDate`（未排的周几），跳过、继续往前。
3. 若该日应出现且 `dayComplete`，`streak++`。
4. 若该日应出现且未完成，停止。
5. 上限看最近 366 天，避免扫全库。

首页长期任务副文案：`streak >= 2` 时加 ` · 已连续 N 天`。一次性任务不显示。

不写入任务对象，避免和补打卡/改周几不一致。

**当日记录**

```js
count, target, completedAt, seconds,
byPiece: {
  [pieceId]: { count, target }
}
```

旧数据没有 `pieces`：所有谱在「未分组」，`bump` 仍写顶层 `count`（和现在一样）。

**行为**

- 曲谱顶栏显示当前曲名；点开列表：未分组 / 各曲名 /「新的一首」。
- 把当前页「移到这首」。
- `bump(+1)`：`byPiece[current].count++`，同时 `count++`（总遍数仍可用于日历条）。
- 首页：若有当前曲，`小星星 3/10`；否则沿用任务级 `3/10`。
- 完成：当前曲达到其 target 时，不自动切下一首；任务完成仍看任务级 count（或：所有曲都完成才算任务完成）。**本方案选：任务完成 = 任务级 count ≥ 任务 target**，当前曲 target 只影响那一行文案。更干净，旧吉他任务不用改目标。

上传新谱默认归入当前曲。

备份 `version` 升到 4：asset 多 `pieceId`；旧备份缺字段当未分组。`schemaVersion` 仍靠 `normalizeTask` 补默认，可不升 IDB version。

## 8. 跳过某一天

```js
task.skipDates: string[]  // 'YYYY-MM-DD'，已去重
```

`taskOnDate` 开头：`if (skipDates.includes(date)) return false`。

今天 / 未来的日历任务行（长期）：按钮 `今天不练`。写入当天日期。再点 `取消跳过`。

首页被跳过的长期任务不出现。连续天数把跳过日当成休息日，不打断。

不允许给过去补跳过（避免改历史完成度）。不允许跳过一次性 `dueDate` 任务（直接改日期或归档）。

## 10. 健身传图 = 完成一次

适用范围：第 0 节之后的 `taskLogsImages`——`completion==='counter'` 且勾了插入图片。**不再**用「有没有曲谱」判断。健身加谱仍算打卡图。

- `addCheckins` 每成功 1 张：`count += 1`（并 `refreshTodayMap`）。
- `removeCheckin`：若当天该任务 count > 0，`count -= 1`。
- **禁止**再走现在的 `syncPhotoDay` 把 count 设成照片张数（那会把手动 +1 盖掉）。
- `photo-log`（画画）维持「张数 = count」的现逻辑；Helpers 不再重复画上传。
- toast：`已记下，今日 3/10`。

有子任务的健身不自动勾子任务，只加 count。

## 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 旧「学习」从计数变成打卡 | 有人当遍数用过 | `day.*` 的 count 保留；首页改勾子。模板文案本来就没有计数 |
| 勾过计数器的自定义被升成 counter | 可能有人只是误点芯片 | 符合「勾了就要出现」；可再改回打卡 |
| `syncPhotoDay` 改健身 count | 已有健身若曾被写成「张数」 | 只对之后的上传用 +1；不回放历史 |
| 当前曲让旧吉他变复杂 | 默认未分组，行为与现在一致 | 不建曲则 UI 不出现切曲 |
| 跳过被当成没练、断连续 | 连续天数把 skip 当休息 | 文案：已跳过 |
| 备份 json 很大 | 图转 base64 | 提示「导出可能较慢」；不改格式 |
| 健身+曲谱后旧图是 helper-image | 互斥规则改之前传的图角色不对 | 新上传走 checkin；旧 helper 仍显示在面板，不自动改角色 |

# 片语 · 复盘

| 项 | 内容 |
|---|---|
| 文档类型 | 项目复盘 |
| 日期 | 2026-08-21 |
| 第一期目标 | 私人金句本：记下、分类、按图配文 |
| 实际交付 | 本机可运行的正式页（`web/` + `server/`），假分类/假看图可走通主路径 |
| 上线形态 | 仅 127.0.0.1，不公网 |

企业里复盘在上线之后开，不问责，只问：**目标达成了吗、过程哪里顺、下次改什么。**

---

## 1. 第一期做成了什么

做成了：

- 太阳封面记下 → 列表确认分类（场景/情绪建议要各点一次）  
- 点卡片才进编辑；复制；筛选；删除  
- 改分类后本机词典学习，同类句优先按词典  
- 按图配文子页（假看图 + 瀑布匹配）  
- 金句在本浏览器 `localStorage`，刷新还在  

没做成（本来就不在第一期，或中途跳过）：

- 完整手工测试  
- 真模型默认开启（有钥匙可关 `FAKE_AI`）  
- 跨设备同步、账号、公开投稿  
- P1：刚用过的不置顶、匹配理由  

主成功标准「用它复制过文案并发过朋友圈」——产品侧尚未验收，复盘时记为 **未验证**。

## 2. 流程走完了哪些，哪些是跳过的

| 步 | 有没有用 | 说明 |
|---|---|---|
| 需求分析 | 有用 | 「检索自己的句子、不生成鸡汤」一直没跑偏 |
| PRD | 有用 | 降级、空结果禁止、无登录边界写清了，后面少吵 |
| 需求评审 | 有用 | 换浏览器不保证、相关分类瀑布，避免做成假需求 |
| 交互设计 + 原型 | 有用也有坑 | 太阳、嵌套、字体都该在原型里试；但原型和正式页容易搞混 |
| 技术方案 / 技术评审 | 有用 | 密钥不进前端、匹配纯函数、只绑本机，上线时还在起作用 |
| 任务拆分 | 有用 | 切片 1 先能记，切片 2 再配图，没有先堆数据库 |
| 开发 | 发生了 | 正式代码在 `web/` `server/`，不是改原型 |
| 测试 | **跳过完整手工** | 自动项绿了；列表跳转、两点建议等没按清单勾完 |
| 上线 | 本机发布 | `npm start` → http://127.0.0.1:8787 |

跳过测试的代价：上线后仍可能在建议芯片、看图失败、微信复制上踩坑。这是产品选择，不是测试「没事」。

---

## 3. 做得好的

**范围守住了。** 社区、生成文案、小程序多次想伸进来，PRD 的「不做」表把它们挡在第一期外。

**失败当主路径设计。** 「匹配失败给列表」写进 P0，比事后补空白页便宜。

**开发中变更有记账。** 列表复制、页面改名、太阳封面、词典学习、确认分类交互，都回写了 PRD/技术方案，没有只改代码。

**本机词典是小而可解释的学习。** 没有假装在训模型，改分类就能复盘「系统为什么这么分」。

---

## 4. 踩过的坑（下次优先改）

**1. 原型当成产品。**  
正式页是 `http://127.0.0.1:5173`（开发）或 `8787`（发布）。`docs/prototype/index.html` 是设计冻结稿。改正式代码后刷新原型，会以为「没有变化」。下次：原型顶上写死「不是产品」，或开发开始后不再用原型演示。

**2. 交互冻结后又大改。**  
太阳光晕、圆/椭圆、标题去掉，发生在「已有交互稿」之后。设计阶段改很便宜；若已写 Vue 再改光晕，成本会高一截。下次：封面动效单独开一页试，试到认了再写进产品。

**3. 「确认分类」来回改了三次。**  
先弹出编辑面板，再改成只到列表，再规定两颗建议都要点。说明验收标准写晚了。下次：涉及「确认」的交互，PRD 里写清「点什么才算确认完」。

**4. 分类点不了。**  
列表层 `transform` 抬高了叠层，编辑面板被挡住。带 `transform` 的层要给弹层更高的 z-index，或弹层挂到根节点。

**5. 测试被跳过。**  
对练习项目可以；对要给别人用的版本不行。下次至少把 `09-测试用例.md` 第 4 节 8 条手点完再 `npm start`。

---

## 5. 给实习生的流程口诀

1. **先写问题，再写功能。** 没有「为谁、卡在哪」，功能会变成愿望清单。  
2. **先写不做。** 比写要做更能保住工期。  
3. **原型上可以想一出是一出；开发中后期要走变更。**  
4. **方案里一句只允许一种实现。** 「可以 200 也可以 503」等于没写。  
5. **演示用正式地址。** 设计稿和产品不要混。  
6. **上线前至少有一张勾选用例。** 跳过测试要写进发布说明。

---

## 6. 第一期还欠的（若有第二期）

按优先级，不是全做：

1. 补完 `09` 手工用例并修缺陷  
2. 有钥匙时关掉 `FAKE_AI`，看真模型分类/看图是否稳  
3. P1：刚用过的句子不要置顶  
4. 仍不要一上来做社区；个人库好用了再谈公开  

---

## 7. 结论

第一期 **流程走完、本机能用、范围没炸。** 最大的产品债是 **手工测试没做**；最大的过程债是 **原型和正式页混用**。这两条记住，下一个小项目会顺很多。

本练习的企业流程到此结束。之后改功能，按「变更 → 改 PRD/方案 → 改代码 → 补一条用例」来，不必再从需求分析重开一轮，除非要做社区或账号。

## 1. 这一步在企业里做什么

技术方案要让开发和测试对下面几件事看法一致：

1. 系统切成几块，块和块怎么说话  
2. 金句存在哪，刷新为什么还在  
3. 分类、看图走哪条链路，密钥不进浏览器  
4. PRD 里的超时、降级、HEIC，技术上怎么落实  
5. 第一期明确不引进哪些重设备（账号、数据库集群、向量库）

写完不是「可以开始堆文件了」，是先拿去 **技术评审**（第 6 步）。

---

## 2. 约束（从需求带过来，不能技术擅自放宽）

| 约束 | 技术含义 |
|---|---|
| 无登录 | 不做账号表、不做跨设备同步 |
| P0 持久化 = 同一浏览器 | 金句可只存在这台浏览器里 |
| 图不长期保存 | 看图请求用完即丢，不做相册、不做磁盘落原图 |
| 只检索已有句子 | 模型只许返回标签，不许写新文案 |
| 保存不依赖分类 | 先写入本地，再异步打标；失败则「其他」 |
| 匹配 10 秒 | 服务端和前端都设超时，到点按低把握降级 |
| 密钥 | `XAI_API_KEY` 只在服务端 |

---

## 3. 总体结构（一句话）

**浏览器里放金句；服务端只当 AI 的门卫。**  
匹配排序在浏览器里按 PRD 瀑布做，不必把整库送到模型。

```text
┌──────────────┐     保存/读取        ┌──────────────┐
│  片语页面     │ ←─────────────────→ │ 浏览器本地库  │
│  Vue 单页    │                      │ localStorage │
└──────┬───────┘                      └──────────────┘
       │ 分类：正文
       │ 看图：当次图片（不落库）
       ▼
┌──────────────┐     SpaceXAI      ┌──────────────┐
│  薄 API      │ ───────────────→  │  grok-4.6    │
│  无业务库    │  文本 + 图片      │  只回标签     │
└──────────────┘                   └──────────────┘
```

为什么不把金句放到服务器：第一期无登录，服务端存了也不知道是谁的；还要处理备份。本地库刚好对齐「同一浏览器还在」。  
为什么必须有服务端：模型密钥不能进前端包，否则任何人打开开发者工具就能盗用。

## 4. 技术选型

| 层 | 选择 | 为什么 |
|---|---|---|
| 页面 | Vite + Vue 3 | 你这边已有 Vue 项目；原型状态（封面/写字/列表/配图）用组件拆最清楚 |
| 样式 | 按交互 token 写 CSS | 不引入重 UI 库，避免做成后台风 |
| 字体 | Google Fonts：Noto Sans SC + Noto Serif SC | 已拍板的摘录风 |
| 本地库 | `localStorage` 一份 JSON | 金句是短文本，几百条远低于配额；第一期不必上 IndexedDB |
| 服务 | Node + **Hono** + `openai` SDK | 轻、和 Fetch 一致；SDK 指到 `https://api.x.ai/v1`；**只监听 127.0.0.1** |
| 模型 | `grok-4.6` | 当前旗舰，支持文本 + 图片输入、文本输出 |
| 密钥 | 环境变量 `XAI_API_KEY`，`.env` 不进 git | 见 SpaceXAI 约定 |

不选：Next.js 全家桶、Postgres、Redis、向量数据库、微信小程序。那些是社区阶段或另一条产品线。

官方看图格式是 **jpg / png**（单张上限 20MB）。PRD 还写了 webp、HEIC：技术上 **上传前在浏览器转成 jpeg**；转不了就用人话提示换 jpg/png，库非空仍给列表。

## 5. 本地数据

键名：`pianyu.quotes.v1`  
整份是一个对象，方便以后加版本迁移。

```text
{
  version: 1,
  quotes: [ { 一条金句 }, ... ]
}
```

一条金句（和 PRD 字段对齐）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 客户端生成，如时间戳 + 随机段 |
| text | string | 1～500 字符，已去首尾空白 |
| scenes | string[] | 1～2 个，词表内；「其他」单独出现 |
| mood | string | 恰好 1 个 |
| sceneUserSet | boolean | 用户改过场景则 true |
| moodUserSet | boolean | 用户改过情绪则 true |
| createdAt | number | 毫秒时间戳，列表默认倒序 |
| updatedAt | number | |
| useCount | number | P1，默认 0 |
| lastUsedAt | number \| null | P1 |

写入规则（前端模块 `quotes.js` 一类，页面自己不准直接 `localStorage.setItem`）：

- 每次改库：**先读出 → 改内存 → 再写回**，避免整份旧快照覆盖  
- 读失败（坏 JSON）：视为空库，`console.warn`，不让页面白屏  
- 保存：校验空、500 字、精确重复、连点锁  
- 分类回写：若该轴 `*UserSet === true`，丢掉这次模型结果  
- 删除：按 id 去掉  
- 复制成功（P1 才更新 useCount）

没有表、没有 SQL。测试时可以清这个 key 当「空库」。  
两页签同时改库：后写覆盖先写，第一期已知限制，不做实时同步。

本机学习词典键名：`pianyu.dict.v1`。用户改场景/情绪（含点建议）时，从句子抽出 2～3 字关键词，给新类加分、给旧类减分；「其他」不入库。新句保存后 **先查词典**，命中的轴不再被 `/api/classify` 覆盖。词典只存在本浏览器，不上传。

## 6. 前端怎么拆（对着原型）

不要把原型 HTML 直接当产品。产品按下面几块搬过去，视觉 token 跟交互稿。

| 模块 | 对应原型 | 职责 |
|---|---|---|
| 封面 | `.cover` | 太阳光晕、点太阳、上滑、封面「按图配文」 |
| 写字处 | `.write-pane` | 输入、保存、收起；保存立刻进本地库再请求分类 |
| 列表 | `.list-pane` | 筛选、卡片、复制、编辑面板、删除确认、底部悬浮按钮 |
| 配图页 | `#page-match` | 上传、匹配中骨架、推荐 3 条、相关列表、返回 |
| 金句仓库 | 无界面 | 读写 localStorage、查重、瀑布排序 |
| AI 客户端 | 无界面 | 调自己的 `/api/*`，带超时 |

状态机（和原型一致）：

```text
cover ──点太阳──► write ──保存/收起──► cover
  │
  └──上滑──► list ──下滑──► cover
                │
                └──按图配文──► match ──返回──► 离开前的 cover 或 list
```

复制：`navigator.clipboard.writeText`；失败则提示长按，正文可选择。

## 7. 服务端接口

服务端 **不存金句、不存图**。两个接口。

### 7.1 `POST /api/classify`

请求：`{ "text": "人间烟火气，最抚凡人心" }`  
成功（HTTP 200）：

```json
{
  "ok": true,
  "scenes": ["日常生活", "美食"],
  "mood": "松弛治愈",
  "sceneConfident": true,
  "moodConfident": true,
  "suggestions": []
}
```

模型失败 / 超时 / 解析失败（仍 HTTP 200）：

```json
{
  "ok": false,
  "scenes": ["其他"],
  "mood": "其他",
  "sceneConfident": false,
  "moodConfident": false,
  "suggestions": []
}
```

缺 `text`：HTTP 400。  
没把握时对应轴为「其他」，`suggestions` 最多 2 个、必须来自词表。

服务端在交给前端之前 **强制清洗**：场景只留词表、最多 2、有真实场景则去掉「其他」；情绪恰好 1 个词表值。

**前端：保存从不依赖本接口。** `ok: false` 或网络错误 → 该句标签为其他。

假分类：服务端 `FAKE_AI=1` 时本接口不调模型，返回同样 JSON 形状（可一律其他）。前端只打 `/api/classify`，不要在页面里另写一套猜词。

### 7.2 `POST /api/look`

`multipart/form-data`，字段 `image`，一张。  
成功（HTTP 200）：`{ "ok": true, "scene": "夜色城市", "mood": "松弛治愈" }`  
图 **恰好 1 个场景 + 1 个情绪**（字段 `scene` 为字符串，不是数组）。  
失败（HTTP 200）：`{ "ok": false, "error": "unsupported" | "too_large" | "timeout" | "failed" }`  
非法请求：HTTP 400。

前端：`ok: false`、HTTP 错、或 **10 秒** 内没回来 → 把握 = 低，按瀑布展示。迟到的成功响应 **丢弃**，不覆盖已经降级的结果。

服务端调模型超时 **8 秒**。

图片处理：

- 浏览器侧：超过约 1600px 的边缩小、转 jpeg、尽量压到 10MB 内  
- 服务端：不写磁盘；读入内存转给模型；请求结束释放  
- 模型侧 jpg/png；webp/HEIC 能在浏览器转就转，不能就 `unsupported`

### 7.3 模型调用（服务端内部）

- Base URL：`https://api.x.ai/v1`  
- 模型：`grok-4.6`  
- 分类：只发正文 + 强制 JSON 的系统说明（词表原文贴进去）  
- 看图：图片 + 「只抽出场景和情绪，不要写文案」  
- `response_format` 用 JSON 对象；解析失败视为分类/看图失败  
- 看图、分类都设比 10 秒略短的超时（例如 8 秒），留给网络余量  

**禁止**：把金句库整包发给模型让它「挑一句」；禁止模型直接输出要展示的句子。展示内容只来自本地库。

## 8. 匹配算法（浏览器，P0）

输入：图的 `scene`（1 个字符串）、`mood`，以及本地 `quotes[]`。  
输出：`level`（高/中/低）、`recommended`（最多 3 条）、`related`（当前瀑布层全部）、`title`（PRD 固定句）。

伪代码：

```text
layer1 = 场景有交集 且 情绪相同
layer2 = 仅场景有交集
layer3 = 仅情绪相同
layer4 = 全部（createdAt 倒序）

若 layer1 非空 且 图的场景、情绪都不是「其他」 → 高
否则若 layer2 或 layer3 非空（含图有一轴为其他但对上了） → 中
否则 → 低

recommended = 按 层1>层2>层3>其余，同层新的在前，取 3 条
related = 当前用到的那一层；若该层空则再放宽，直到有句子
库 < 20 条时 related 必须有（通常直接能看到几乎全部）
看图失败：level=低，related=全部
```

必须做成 **纯函数**（不读 localStorage、不碰 DOM），例如 `matchQuotes(quotes, { scene, mood })`。切片 2 先测这个函数再接线。看图失败时由页面直接把 `related` 设为全部，不必经过模型。

## 9. 异常怎么落到代码

| PRD 情况 | 技术动作 |
|---|---|
| 正文空 / 超 500 / 重复 / 连点 | 纯前端，不打 API |
| 分类超时失败 | 本地已保存；标签其他 |
| 分类中用户已改分类 | 回写时看 `*UserSet` |
| 看图失败 / 超时 | 不存图；把握低；列表仍可复制 |
| 格式不支持 | 提示换 jpg/png |
| 复制失败 | catch，提示长按 |
| 无网络保存 | 本地写入仍成功（localStorage 不需要网）。分类可以失败。配图必须网，失败走低把握 |
| 无网络且 localStorage 被关 | 提示存不了；这是极端环境，评审可标为已知限制 |

「有网络时保存必成功」：保存路径不经过 `/api/classify`。分类是附加请求。

## 10. 安全与隐私

- 前端包里不得出现 `XAI_API_KEY`、不得直连 `api.x.ai`  
- 服务监听 **127.0.0.1**，第一期无鉴权、不做公网部署  
- 不打日志原文图片；服务端日志最多记错误码和耗时  
- 不把用户金句送到除分类以外的任何第三方  
- 金句正文用 Vue 文本插值渲染，禁止 `v-html`

## 12. 和交付切片怎么对齐

| 切片 | 技术内容 |
|---|---|
| 1 | Vue 搬家：封面 / 写字 / 列表 / 本地库 / 复制 / 编辑删除。分类可先假接口，再接真模型 |
| 2 | `/api/look` + 瀑布函数 + 配图页降级 |
| 3（P1） | 使用次数、匹配理由、列表上改轴 |

切片 1 即使模型还没接上，你也能自己用：记下、分类先全是「其他」、上滑复制。这是企业里「先打通主路径再接 AI」的常用切法。

## 13. 风险

| 风险 | 处理 |
|---|---|
| 模型不按 JSON 回 | 服务端解析失败 → 当失败；提示词里贴死词表 |
| HEIC 转 jpeg 各浏览器不一致 | 失败走 PRD 文案，不赌 100% 能转 |
| 微信内置浏览器剪贴板 | 已有长按兜底 |
| localStorage 被用户清掉 | 库空，产品允许；不作为事故 |
| 模型费用 | 每次保存、每次看图各 1 次调用；第一期量小 |

## 1. 企业里测试怎么做

1. **先写用例再点。** 用例来自 PRD 验收节 + 开发中已合入的变更（记下进列表、两点建议、本机词典）。  
2. **主路径、失败路径都要。** 只测「能记下」不够。  
3. **能自动的自动，必须眼看的手测。** 瀑布函数、词典、接口可以用脚本；「列表会不会跳」要打开页面。  
4. **失败要可复现：** 步骤、期望、实际、是否挡住上线。

结果标记：

- **通过**：和期望一致  
- **待手工**：脚本验不了，要在 5173 上点  
- **失败**：和期望不符，要修再测  
- **不测**：本期范围外

## 4. 建议的手工顺序（约 10 分钟）

打开 http://127.0.0.1:5173/

1. 空保存 → A1  
2. 写「先吃饭，再想人生」保存 → 应在列表，不弹编辑面板 → A2  
3. 写「嘻嘻」保存 → 两颗建议；先点场景建议，情绪建议还在 → B1  
4. 再点情绪建议 → B2  
5. 点进卡片改分类、删一条、筛美食 → B3–B5  
6. 刷新 → D1  
7. 封面「按图配文」传一张 jpg → C2  
8. 复制 → C5  

发现问题记在下面，修完把该条改成「通过」。

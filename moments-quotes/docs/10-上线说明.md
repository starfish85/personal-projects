## 1. 企业里「上线」指什么

上线不是把代码往磁盘一丢。通常包括：

1. 打一个可运行的包（构建）  
2. 配环境（密钥、假/真模型）  
3. 用生产方式启动（不是改一行刷新的开发服务器）  
4. 写清打开地址、已知限制、出问题怎么回滚  

片语第一期按技术评审：**服务只绑 127.0.0.1，不上公网。**  
所以这里的「上线」= **你这台电脑上，用一条命令长期打开给自己记句子。**

## 2. 打开哪一个

| 地址 | 是什么 | 上线用不用 |
|---|---|---|
| http://127.0.0.1:8787 | 构建后的正式页 + 接口（推荐自己用） | 用 |
| http://127.0.0.1:5173 | 开发热更新 | 改代码时用 |
| `docs/prototype/index.html` | 设计稿 | **不用** |

金句在浏览器 `localStorage` 里。换浏览器或清站点数据，库会空。这是已拍板的限制。

## 3. 本机发布步骤

在 `personal-projects/moments-quotes`：

```bash
# 第一次
cp .env.example .env
npm --prefix server install
npm --prefix web install

# 以后每次发布（构建前端 + 只起一个服务）
npm start
```

浏览器打开：**http://127.0.0.1:8787**

停掉：终端里 Ctrl+C。

`.env` 建议：

```
FAKE_AI=1
PORT=8787
```

要接真模型时：填 `XAI_API_KEY`，设 `FAKE_AI=0`，再执行 `npm start`。密钥只放 `.env`，已在 `.gitignore`，不要提交、不要写进前端。

开发改代码仍用：

```bash
npm run dev:server
npm run dev:web
```

然后打开 5173。5173 会把 `/api` 转到 8787。

## 4. 发布检查（跳过测试后的最低线）

上线前至少确认：

- [ ] 手机扫码打开 GitHub Pages，或本机打开 8787 / 5173，不要打开原型 HTML  
- [ ] `.env` 不在 git 里  
- [ ] 服务日志里是 `127.0.0.1`，不是 `0.0.0.0`  
- [ ] 能记下、刷新还在、能复制  
- [ ] 没有把 `XAI_API_KEY` 写进 `web/` 源码  

未做完整手工用例（见 `09-测试用例.md`）。已知可能问题：建议芯片、看图失败、微信内复制，上线后仍可能碰到。

## 5. 回滚

没有线上服务器可回滚。本机：

- 停掉当前 `node` 进程  
- 需要的话 `git checkout` 回到上一版再 `npm start`  
- 金句在浏览器里，回滚代码一般不会清库；清站点数据会清库  

---

## 6. 明确不做的「上线」

- 买域名、备案、云主机（GitHub Pages 的 HTTPS 网页可以扫码）  
- 把带密钥的分类接口暴露到公网  
- App Store / 小程序提交  

那些是以后做社区时另立的发布流程。

## 7. GitHub Pages（扫码打开）

没有小程序账号时，用 **HTTPS 网页 + 二维码**，微信/相机扫码即可打开。

地址：https://pianyu.pages.dev/

已做成 PWA。Safari 分享 → 添加到主屏幕；Chrome 菜单 → 安装应用。不要用微信内置浏览器安装。

发布（在本项目目录）：

```bash
zsh scripts/publish-pages.sh
```

这是静态站：**不会把密钥放到 GitHub。** 分类用页面内的规则 + 本机词典；看图没有后端时按「没看清」降级，列出全部金句，不出现空白页。真模型看图仍需本机 `npm start`。

微信里打开可能复制失败，正文可长按，这是已有兜底。

二维码见 `docs/qr-pianyu.png`（发布后按上面地址生成）。
